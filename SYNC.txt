====================================================================
線上端 (hub) 與門市分店 (node) 的資料同步
====================================================================

角色 (環境變數 SYNC_ROLE)
- standalone：單機 (預設)。不同步，所有功能與以前相同。
- node：門市分店。SQLite、可完全離線營業，背景與線上端同步。
- hub：線上端。PostgreSQL、Docker 部署 (DEPLOY.txt)；提供線上點餐與總部後台，是所有分店資料的匯集點。
一個線上店家 (tenant) 可以有多家分店；分店之間不直接連線，都透過線上端交換資料。

同步的資料
  資料                                   方向           合併方式
  菜單、套餐、加料、優惠券、紅利設定、員工  雙向           修改時間較新者為準 (LWW)
  會員資料 (姓名、手機、PIN、人臉特徵)       雙向           修改時間較新者為準
  會員點數                                雙向           點數異動帳 (point_ledger) 合併後重算合計
  會員持有券 (含到期時間、發放批次)       雙向           修改時間較新者為準；撤回 = 刪除紀錄同步
  紅利兌換憑證                            雙向           狀態只往前走 (可用 → 已退點 → 已使用)
  訂單與明細                              雙向 (見下)    狀態只往前走 (製作中 → 已出餐 → 已取餐；已取消最優先)
  日誌 (登入、稽核、顧客進場)              分店 → 線上   只新增
  促銷活動、會員等級、分類翻譯             雙向           修改時間較新者為準 (等級以名稱、翻譯以分類名稱合併)
  會員儲值金                              雙向           儲值金異動帳 (wallet_ledger) 合併後重算餘額 (同點數)
  收款紀錄 (payment_record)               分店 → 線上   只新增 (線上端彙整各店付款方式報表)
  餐後評分 (order_feedback)               分店 → 線上   只新增 (線上端「顧客評價」彙整各店)
  集點卡章數 (stamp_ledger)               雙向           只新增；章數 = 合計 (同點數)
  禮物卡 (gift_card) 與異動 (gift_card_ledger)  雙向     卡片以卡號合併；餘額 = 異動合計 (各店售出 / 扣款合併)
  總部設定 (hq_setting)                   線上 → 分店   修改時間較新者為準；分店上傳的一律忽略 (方向 down)
  退款、電子發票                          分店 → 線上   修改時間較新者為準 (各台主機自己開立 / 自己退款)
  營業費用 (expense)                      分店 → 線上   修改時間較新者為準；線上端記下登錄的分店 (node_uuid)，
                                                         損益表可依分店篩選；線上端不可修改分店登錄的費用、分店也不可藉同步改別家分店或線上端的費用 (列入衝突)；
                                                         刪除為標記刪除
  刪除                                   雙向           刪除紀錄 (sync_tombstone)；刪除優先，不會被舊的修改復活
  不同步：各分店的庫存 (stock / total_stock / 售完)、取餐號計數、登入鎖定紀錄、會員累積消費 (各機重算)，
          以及門市本機設定與資料：系統設定 (store_setting，含外部服務金鑰)、交班、桌位結帳批次、印表機與工作站、
          列印佇列、原物料與配方、訂位 / 候位、打卡與班表、簡訊驗證碼、員工登入工作階段 (staff_session)、
          供應商 / 採購單 / 原料批號、員工時薪 (staff_account.hourly_wage)。
  即時看板在線上端彙整各分店同步上來的訂單 (人事成本率依各台主機自己的打卡紀錄計算，不跨店彙整)。
  員工帳號的兩步驟驗證金鑰與「登出所有裝置」次數 (session_epoch) 會同步；分店不可變更負責人的驗證金鑰 / 備用碼。
  會員動態條碼的金鑰 (user.qr_secret) 隨會員同步，任何分店都能驗證會員在線上端開啟的條碼。
  推薦碼 (user.referral_code) 與推薦人 (referred_by_uuid) 隨會員同步；點數到期只在線上端 (或單機) 執行，
  到期扣點以異動帳同步到各分店 (分店不執行，避免重複扣點)；點數到期提醒日 (points_notice_on) 不同步。
  線上端執行到期時，分店可能已 (同步前) 用掉同一批點數：線上端收到分店上傳的點數異動後，依時間先進先出重算每一次到期
  「當時尚未用掉」的量，與記錄不同時補一筆 expire_fix (會同步)，不會同一批點數被到期又被使用而多扣。
  自有外送的地址 / 外送費隨訂單同步；配送狀態 (delivery_status) 只往前走 (待派車 → 已指派 → 配送中 → 已送達 / 失敗)，
  在出餐分店派車後同步回線上端；同一階段改派外送員以較新的修改為準。
  預約取餐時間 (order.pickup_at) 隨訂單同步；餐後評分 (order_feedback) 只由分店上傳到線上端彙整；
  桌邊呼叫服務 (service_call) 為門市本機資料，不同步。
  線上訂單的繳費資訊 (payment_note、payment_due_at) 隨訂單同步；綠界退刷只在線上端執行，
  成功後付款狀態改為「已退款」同步回分店 (分店取消的線上信用卡訂單，同步上線上端後由線上端退刷)。

訂單
- 每張訂單有 node_uuid (負責出餐的分店)。分店自己的訂單上傳到線上端；線上端只把「該分店負責出餐」的訂單下發給該分店。
- 線上點餐 (只限會員)：顧客在線上端選取餐分店 → 以該分店回報的庫存快照檢查並預扣 → 綠界線上付款
  → 付款完成後訂單才同步給分店 (待付款、逾時未付的訂單不會送出) → 分店收到後扣實體庫存、編取餐號、出現在廚房看板
  → 取餐號與後續狀態同步回線上端。訂單取餐號在分店收到前為 0 (顯示「待分店確認」)。
- 分店離線超過 SYNC_NODE_OFFLINE_AFTER 秒 (預設 120)，線上端暫停該分店的線上點餐。
- 線上端的庫存快照 = 分店回報的本機庫存 − 已在線上成立 (含待付款) 但分店還沒收到的線上訂單份數
  (分店收到時才扣本機庫存並編取餐號；取餐號為 0 代表尚未送達)。分店的庫存隨上傳的最後一頁送出，
  線上端先套用分店已收到的訂單再計算，避免回報值把線上已預扣的份數蓋回來而重複販售。
- 線上端快照仍可能落後 (分店現場賣掉後尚未回報的幾秒內)：此時線上訂單照常成立，分店庫存扣到 0 並標示售完，
  同時以監控通知提醒店員「線上訂單送達時庫存不足」，聯絡顧客改換餐點或取消退款。
- 任何一端取消訂單：該端回補點數/優惠券 (以異動帳同步)；實體庫存由出餐分店在收到「已取消」時回補。
- 分店收到線上訂單時本機庫存不足，訂單仍成立 (庫存扣到 0 並標示售完)，由店員決定是否取消。
- 已退款金額 (refunded_amount) 只增不減；LINE Pay 扣款中 (authorizing) 的訂單收到扣款成功的版本時改為已收款。
- 訂單的交班、桌位結帳批次、桌位、各品項的工作站完成時間是本機欄位，不同步。

會員與點數 (跨分店共用)
- user.points 是 point_ledger 的合計。每一次加減點都寫一筆異動 (結帳贈點、折抵、兌換、退點、後台調整…)。
- 兩家分店斷線時各自扣點，同步後兩筆異動都保留，合計正確；極端情況下 (兩邊同時花光) 合計可能短暫為負，
  負數時無法再折抵或兌換，直到補回點數。線上端合併後發現點數為負會以監控通知店家。
- 會員券在兩個資料庫同步前被同時使用 (分店現場 + 線上，或兩家分店)：兩張訂單都已成立，無法即時互鎖。
  線上端收到分店上傳的訂單後，以「未取消的訂單」為準：仍有訂單使用的券一律是已使用 (另一邊較新的取消退券
  不會把它改回未使用)；同一張券有兩張以上未取消的訂單時通知店家 (補收差額或取消其中一張)。
- 推薦好友獎勵每位新會員一次：新會員的第一筆訂單在兩家分店同步前同時成立時兩邊各發一次，線上端保留最早的一次，
  其餘以 referred_dup / referral_dup 沖銷 (新會員與推薦人各一筆，會同步) 並通知店家；之後取消該訂單只扣回淨得的點數。
- 集點卡在兩家分店同步前同時集滿 (各兌換一次獎勵)：章數合計變負數 (畫面顯示 0，之後集的章先補回)，線上端通知店家。
- 禮物卡、儲值金同樣以異動帳合併：兩家分店同步前同時用光，同步後各處餘額一致 (可能為負數)，線上端通知店家補收差額。
- 寄杯：商品 (pass_product) 與會員持有的寄杯 (member_pass) 雙向同步；剩餘次數是 pass_ledger 的合計 (本機欄位，合併後重算)，
  兩家分店同步前同時用完同一張寄杯會變負數，線上端通知店家。桌位平面圖與桌邊線上結帳 (table_payment) 為門市本機資料。
- 套餐任選群組 (combo_option_item.choice_group / extra_price) 隨套餐同步；訂單記錄的是顧客實際選的配餐。

多分店營運
- 分店價格 / 上下架 (branch_menu_override)：只由線上端設定、只下發給該分店 (其他分店收不到；分店上傳的會被拒絕)。
  清除設定時改為空白而不刪除，避免同一組分店 / 餐點新舊資料互撞。線上點餐依顧客選擇的取餐分店套用。
- 分店名單：線上端在新增 / 改名 / 停用分店與分店第一次連線時寫入總部設定 (hq_setting 的 branch_sites)，分店據此選擇叫貨對象。
- 叫貨 / 調撥單 (stock_transfer)：只送給出貨方與收貨方。狀態只往前走 (待出貨 → 取消 / 拒絕 → 已出貨 → 已收貨)；
  線上端檢查操作者 (出貨 / 拒絕只能由出貨方、收貨 / 取消只能由收貨方，建立叫貨單只能是收貨方、建立調撥單只能是出貨方)，
  不符的上傳列入衝突。收貨方取消與出貨方出貨在同步前同時發生時以「已出貨」為準 (貨已離開)：不論哪一邊先送到線上端，
  線上端與收貨方都會收到通知，收貨方照常收貨或安排退回。
  原料庫存屬各主機本機資料：出貨 / 收貨的那台主機在操作當下增減自己的原料 (依名稱對應)，不會因同步重複增減。
- 會員的「拒絕行銷」(user.marketing_opt_out) 隨會員資料同步；自動行銷活動 (marketing_campaign / campaign_send) 只存在線上端
  (單機則在本機)，發出的會員券照常同步到各分店。
- 訂位、訂金、訂位提醒、交班為門市本機資料 (不同步；線上端不提供訂位 / 候位頁面)；員工異常偵測在線上端可看各分店的作廢 / 退款 / 折扣 (訂單與退款會上傳)，
  交班帳差只在門市看得到。
- API 金鑰、Webhook、裝置、封存為各主機本機資料 (不同步)：在哪台主機設定就由哪台主機提供 / 送出。
- 團體預購 (group_order / group_order_entry) 為門市本機資料 (線上端不提供)；送單後建立的訂單照常上傳線上端。
- 點餐機斷線暫存單存在點餐機瀏覽器，補送到門市主機後才成為訂單 (之後照常同步)；門市主機與線上端之間斷線時不影響點餐。
- 原料成本 / 售價歷史 (cost_history) 為各主機本機資料：每台主機記錄自己資料庫的變動 (分店收到總部改價時也會記一筆，
  修改者為 system)。損益表的手續費率屬「損益表」系統設定 (可由總部設定下發)；人事成本依各主機的打卡紀錄，
  線上端依分店篩選時人事成本為 0 (員工時薪不同步)。
- 舊資料封存只刪本機資料，不產生同步刪除紀錄 (線上端與其他分店保留原資料，線上端可自行封存)。會員的 archived_spent 為本機欄位。
- 單品作廢：order_item 的作廢份數只增不減 (剩下份數跟著更新)，只有出餐分店可作廢；桌邊未結帳訂單的應付金額只會變少。
- 套餐訂單記錄賣出當下的配餐 (order_item.combo_sides，餐點 uuid)：線上套餐訂單送到分店前總部改了套餐內容，
  分店仍扣當時的配餐；取消時也回補當時的配餐 (舊訂單沒有記錄時才用目前的套餐內容)。
- 同一個資料庫內 (同一家店的點餐機 / 桌邊 / POS，或線上端的多張線上訂單) 不會發生：券以條件式 UPDATE 核銷、
  點數以條件式 UPDATE 扣點；會員結帳時先鎖住會員資料列 (扣庫存之後)，公開代碼的「每人限用次數」、
  集點卡集滿、推薦好友獎勵都依序處理，不會重複發放。
  送出時可用、結帳時已被其他通路用掉的券 / 點數，結帳會失敗並說明 (409，coupon_unavailable / points_changed)，
  不會默默改用原價或只折一部分成立訂單；點餐機會重新載入、POS 會重新讀取會員資料讓收銀再確認金額。
- 同一支手機在兩家分店各自註冊：線上端會把後到的那筆合併到先到的那筆 (sync_alias)，
  兩邊的訂單、點數、優惠券都歸到同一位會員；分店收到合併結果後也在本機合併。
- 加料選項 (分類 + 名稱)、優惠券 (代碼)、紅利設定 (每店一筆)、員工 (帳號) 也以相同方式合併。
- 員工帳號在整個系統唯一：分店建立的帳號名稱若已被其他店家使用，線上端會拒收並顯示在分店的「同步狀態」頁。

變更追蹤 (app/sync/tracking.py)
- 每列同步資料有 sync_rev：本資料庫的提交序號。交易中先寫入暫時標記，提交前把 sync_clock + 1 並換成正式序號。
  sync_clock 那一列鎖到提交結束，所以序號順序就是提交順序，讀到序號 N 時 N 以前的交易都已提交，不會漏資料。
- 同步時只傳送 sync_rev 大於對方游標的列，並依外鍵相依順序分頁傳送；中斷後從上次的游標重傳 (重複套用不影響結果)。
- 只修改本機專屬欄位 (庫存、點數合計) 不會標記，也不會改變 updated_at。
- tests/test_sync_invariants.py 在整個測試套件跑完後檢查：沒有殘留標記、每位會員的點數 = 異動帳合計。

通訊 (app/sync/hub.py、app/sync/node.py)
- HTTPS + 分店權杖 (Authorization: Bearer kn_…)。權杖在線上端「分店管理」產生，只存雜湊值。
- POST /api/sync/v1/hello     第一次連線：分店取得自己的 uuid，本機店家改用線上店家的 uuid
- POST /api/sync/v1/push      分店上傳變更與庫存快照；回應拒收的資料、合併結果、線上缺少的餐點圖片
- GET  /api/sync/v1/pull      分店下載變更；wait 參數為長輪詢秒數 (有新的線上訂單時立即回應)
- GET/PUT /api/sync/v1/media/menu/<路徑>   餐點圖片 (會員人臉照片不上傳，只同步人臉特徵)
- 分店背景執行兩個執行緒：上傳 (本機提交後立即觸發 + 每 SYNC_INTERVAL 秒)、下載 (長輪詢 SYNC_LONG_POLL 秒)。

安全限制 (分店權杖外流或分店電腦被入侵時，影響範圍只限該店家的一般資料；tests/test_sync_security.py)
- 負責人 (owner) 帳號只能在線上端建立、修改 (帳號、密碼、角色、停用) 與刪除；分店上傳的負責人帳號、
  把員工升為負責人、刪除負責人的刪除紀錄一律拒收 (預設店家的負責人是平台管理者)。
- 餐點圖片 / 會員照片路徑必須是固定格式 (不可含 ../)；兩端套用前都檢查，刪除檔案時再限制在上傳資料夾內。
- 圖片 API 只能讀寫「本店餐點正在使用」的圖片，且已存在的圖片不覆蓋。下載的圖片必須是有效圖片檔。
- 線上端不接受與其他店家資料相同的 uuid；別名 (sync_alias) 只在同一店家內生效。
- 單次上傳最多 5000 列、庫存回報最多 5000 筆。
- 分店取消已線上付款的訂單：線上端標記「需退款」。
- 撤回人臉同意或刪除會員：各分店收到同步後一併刪除本機照片檔。
- 仍信任分店的範圍 (同一店家的分店視為店家自己的設備)：菜單、優惠券、會員資料與點數異動、一般員工帳號。
  分店也會收到店家員工的密碼雜湊 (scrypt，讓員工在各分店用同一組帳密登入)，分店電腦請比照 POS 主機妥善保管。

限制 (設計上的取捨)
- 以修改時間判斷新舊，門市電腦時間必須正確 (自動校時)。
- 線上點餐的庫存是分店回報的快照，回報之間的短暫時間可能超賣，由分店收單時處理 (與外送平台相同)。
- 線上付款只串接綠界的付款與查詢；取消已付款訂單的退款需在綠界廠商後台辦理。
- 不同分店各自建立的同名菜單品項不會自動合併 (無法確定是否為同一品項)，請以一處為主建立菜單。
