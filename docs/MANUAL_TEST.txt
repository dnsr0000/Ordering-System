====================================================================
人工實測步驟 (全功能)
====================================================================

用途：上線前或大改版後，由人實際操作一遍，確認畫面與流程正確。
自動化測試 (pytest) 已涵蓋大部分邏輯；這份文件著重「人看得到、摸得到」的部分：
畫面顯示、列印、手機、相機、跨裝置即時更新、實際刷卡、同步。

每個項目包含：項目 / 步驟 / 預期，以及結果欄 (□ 通過 □ 失敗) 供勾選與備註。
編號規則：A-01 = A 區第 1 項。失敗時記下編號、畫面截圖與時間，方便對照後台稽核紀錄。
章節 (每個主題一章)：
  A 啟動、後台登入與系統設定    B 員工帳號、權限與帳號安全    C 菜單、套餐與原物料
  D 會員、等級與會員行銷        E 自助點餐 (點餐機)           F 優惠券、紅利商城與促銷
  G POS 收銀、金流與發票        H 廚房、取餐、叫號看板與顧客通知   I 訂單狀態、取消與同時操作
  J 桌邊掃碼點餐與桌位          K 報表、分析與 AI             L 備份、還原與版本更新
  M 隱私權與個資                N 多店家與店家管理            O 門市與線上端同步、多分店
  P 線上點餐與付款              Q 安全性抽查                  R 換日、長時間運作與系統維運
  S 外送、訂位與候位            T 打卡與排班


--------------------------------------------------------------------
0. 測試前準備
--------------------------------------------------------------------
- 備份：先複製 database\ 與 uploads\ 到其他資料夾 (測試會新增訂單、會員；測完可還原)。
  也可以另外複製一份專案資料夾專門測試，在 .env 指定不同的 PORT (例如 5050)。
- 安裝與啟動：
    .venv\Scripts\activate
    pip install -r requirements-store.txt        (門市套件；含人臉辨識用的 numpy / opencv-python-headless)
    python serve_windows.py
  第一次啟動會在背景下載人臉模型檔到 models\ (需能連 github.com；或先執行 flask --app run models download)；
  後台「系統監控與備份」的「人臉辨識登入」方塊顯示「可用」才能測 D-04。
- .env 已設定 ADMIN_USERNAME / ADMIN_PASSWORD (下文稱「負責人帳號」)。
- 裝置：
  - 電腦 A：伺服器本機，開 Chrome (後台 / POS / 點餐機)。
  - 電腦 B 或平板：同一個區網，開 http://伺服器IP:5000/kitchen (廚房) 與 /counter (叫號看板)。
  - 手機一支：連店內 Wi-Fi (與伺服器同一個網路)。
  - 有相機的裝置 (筆電內建鏡頭即可)：測人臉。
  - 熱感應收據機 (若有)：測列印。
- 第二個瀏覽器 (或無痕視窗)：同時登入不同角色時使用。
- 測試用資料 (B 區建立)：店長 t_manager、櫃檯 t_pos、廚房 t_kitchen (密碼皆至少 10 碼)。
- 後台頁面位置：所有後台頁都從左側選單進入 (今日營運 / 菜單 / 顧客與行銷 / 通路 / 人員 / 報表 / 系統)；
  下文「菜單與套餐」= /admin/menu、「會員」= /admin/members、「回饋商城與優惠券」= 後台首頁的分頁、
  「系統設定」= /admin/settings、「系統監控與備份」= /admin/system。
- 線上端 (O、P 區與標示「線上端」的項目) 需要 Docker；不測同步與線上付款時可略過。
- O-08、O-09 (分店價格、叫貨 / 調撥) 需要線上端 + 至少一家分店；J-15 桌邊線上結帳、S-09 訂位訂金需門市主機能從外部以
  HTTPS 連線 (PUBLIC_BASE_URL，可用 ngrok)；R-09 Webhook 需要一個 https 接收網址 (例如 webhook.site)。
